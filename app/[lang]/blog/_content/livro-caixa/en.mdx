At Charita, a donation platform that charges campaigns no fee, money is recorded in a double-entry ledger inside Postgres. The database itself enforces two rules: every transaction adds up to zero, and nothing that was written can be changed or deleted.

## The tables

Each movement of money is a transaction with two or more entries. An entry is a signed amount on one account. Without the automatic creation timestamps, the tables look like this:

```sql
create table ledger_accounts (
  id uuid primary key,
  key varchar(255) not null,
  currency varchar(3) not null,
  unique (key, currency)
);

create table ledger_transactions (
  id uuid primary key,
  occurred_at timestamp(0) not null
);

create table ledger_entries (
  id uuid primary key,
  transaction_id uuid not null references ledger_transactions on delete restrict,
  account_id uuid not null references ledger_accounts on delete restrict,
  amount bigint not null check (amount <> 0)
);
```

Amounts are stored in each currency's smallest unit, so 5000 is fifty reais. Each account has a single currency.

## Every transaction adds up to zero

A trigger checks that the entries of a transaction add up to zero and that they all use the same currency:

```sql
create function ledger_transaction_must_balance() returns trigger as $$
declare
  currencies integer;
  total bigint;
begin
  select count(distinct a.currency), coalesce(sum(e.amount), 0)
    into currencies, total
    from ledger_entries e
    join ledger_accounts a on a.id = e.account_id
   where e.transaction_id = new.transaction_id;

  if currencies > 1 then
    raise exception 'ledger transaction % mixes currencies', new.transaction_id;
  end if;

  if total <> 0 then
    raise exception 'ledger transaction % is off by %', new.transaction_id, total;
  end if;

  return null;
end;
$$ language plpgsql;

create constraint trigger ledger_entries_must_balance
  after insert on ledger_entries
  deferrable initially deferred
  for each row execute function ledger_transaction_must_balance();
```

It is `deferrable initially deferred` because entries are written one at a time, and after the first one the sum is not zero yet. With the check deferred to `commit`, the database checks once all the entries are in. If the sum does not balance, nothing is saved.

## Nothing is changed or deleted

Another trigger refuses `update` and `delete`:

```sql
create function ledger_is_append_only() returns trigger as $$
begin
  raise exception 'the ledger is append only: % on % is not allowed',
    tg_op, tg_table_name;
end;
$$ language plpgsql;

create trigger ledger_entries_append_only
  before update or delete on ledger_entries
  for each row execute function ledger_is_append_only();
```

The example shows `ledger_entries`, and `ledger_transactions` and `ledger_accounts` have the same trigger.

To refund a donation, a new transaction is written with the original entries and the sign flipped. The original stays in the history.

## On the transparency page

The platform fee is an account like any other and has never received an entry. Charita's transparency page builds its statement straight from the ledger, and the statement adds up to zero in each currency.
