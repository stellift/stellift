At Charita, a donation platform that charges campaigns no fee, the money lives in a double-entry ledger inside Postgres. The database itself looks after its rules, with two triggers. One won't save a transaction that doesn't add up to zero. The other won't let anything be changed or deleted.

## The tables

Each movement of money is a transaction with two or more entries, and each entry is a signed amount on one account. Leaving out the creation timestamps Ecto adds, the tables look like this:

```sql
create table ledger_accounts (
  id uuid primary key,
  key varchar(255) not null,
  currency varchar(3) not null,
  unique (key, currency)
);

create table ledger_transactions (
  id uuid primary key,
  occurred_at timestamp(0) not null
);

create table ledger_entries (
  id uuid primary key,
  transaction_id uuid not null references ledger_transactions on delete restrict,
  account_id uuid not null references ledger_accounts on delete restrict,
  amount bigint not null check (amount <> 0)
);
```

Amounts are stored in the currency's smallest unit, so 5000 is fifty reais. Each account has a single currency.

## The trigger that checks the sum

```sql
create function ledger_transaction_must_balance() returns trigger as $$
declare
  currencies integer;
  total bigint;
begin
  select count(distinct a.currency), coalesce(sum(e.amount), 0)
    into currencies, total
    from ledger_entries e
    join ledger_accounts a on a.id = e.account_id
   where e.transaction_id = new.transaction_id;

  if currencies > 1 then
    raise exception 'ledger transaction % mixes currencies', new.transaction_id;
  end if;

  if total <> 0 then
    raise exception 'ledger transaction % is off by %', new.transaction_id, total;
  end if;

  return null;
end;
$$ language plpgsql;

create constraint trigger ledger_entries_must_balance
  after insert on ledger_entries
  deferrable initially deferred
  for each row execute function ledger_transaction_must_balance();
```

The `deferrable initially deferred` is there because entries go in one at a time. After the first one the sum isn't zero yet, so the check waits for `commit`, when they're all in. If the sum doesn't balance, the `commit` fails and nothing is saved. The same trigger also refuses a transaction that mixes currencies.

## The trigger that won't let anything change

```sql
create function ledger_is_append_only() returns trigger as $$
begin
  raise exception 'the ledger is append only: % on % is not allowed',
    tg_op, tg_table_name;
end;
$$ language plpgsql;

create trigger ledger_entries_append_only
  before update or delete on ledger_entries
  for each row execute function ledger_is_append_only();
```

`ledger_transactions` and `ledger_accounts` have the same trigger.

So refunding a donation means writing another transaction with the same entries and the sign flipped. The original transaction stays where it is.

This is the ledger Charita's transparency page shows. The platform fee is an account like any other, and it has never received an entry.
