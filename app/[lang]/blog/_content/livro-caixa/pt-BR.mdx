Na Charita, plataforma de doações que não cobra taxa das campanhas, o dinheiro fica num livro-caixa de partidas dobradas dentro do Postgres. Quem cuida das regras dele é o próprio banco, com dois gatilhos. Um não deixa gravar transação que não some zero. O outro não deixa alterar nem apagar nada.

## As tabelas

Cada movimento de dinheiro é uma transação com dois ou mais lançamentos, e cada lançamento é um valor com sinal numa conta. Tirando as colunas de data de criação que o Ecto acrescenta, as tabelas são estas:

```sql
create table ledger_accounts (
  id uuid primary key,
  key varchar(255) not null,
  currency varchar(3) not null,
  unique (key, currency)
);

create table ledger_transactions (
  id uuid primary key,
  occurred_at timestamp(0) not null
);

create table ledger_entries (
  id uuid primary key,
  transaction_id uuid not null references ledger_transactions on delete restrict,
  account_id uuid not null references ledger_accounts on delete restrict,
  amount bigint not null check (amount <> 0)
);
```

Os valores ficam na menor unidade da moeda, então 5000 são cinquenta reais. Cada conta tem uma moeda só.

## O gatilho que confere a soma

```sql
create function ledger_transaction_must_balance() returns trigger as $$
declare
  currencies integer;
  total bigint;
begin
  select count(distinct a.currency), coalesce(sum(e.amount), 0)
    into currencies, total
    from ledger_entries e
    join ledger_accounts a on a.id = e.account_id
   where e.transaction_id = new.transaction_id;

  if currencies > 1 then
    raise exception 'ledger transaction % mixes currencies', new.transaction_id;
  end if;

  if total <> 0 then
    raise exception 'ledger transaction % is off by %', new.transaction_id, total;
  end if;

  return null;
end;
$$ language plpgsql;

create constraint trigger ledger_entries_must_balance
  after insert on ledger_entries
  deferrable initially deferred
  for each row execute function ledger_transaction_must_balance();
```

O `deferrable initially deferred` está aí porque os lançamentos entram um de cada vez. Depois do primeiro, a soma ainda não é zero, então a conferência fica para o `commit`, quando todos já entraram. Se a soma não fechar, o `commit` falha e nada é gravado. O mesmo gatilho recusa transação que misture moedas.

## O gatilho que não deixa mudar nada

```sql
create function ledger_is_append_only() returns trigger as $$
begin
  raise exception 'the ledger is append only: % on % is not allowed',
    tg_op, tg_table_name;
end;
$$ language plpgsql;

create trigger ledger_entries_append_only
  before update or delete on ledger_entries
  for each row execute function ledger_is_append_only();
```

`ledger_transactions` e `ledger_accounts` têm o mesmo gatilho.

Com isso, estornar uma doação é gravar outra transação com os mesmos lançamentos e o sinal trocado. A transação original continua lá.

É esse livro-caixa que a página de transparência da Charita mostra. A taxa da plataforma é uma conta como qualquer outra, e nunca recebeu lançamento.
