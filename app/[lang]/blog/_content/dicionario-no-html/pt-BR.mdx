Medindo o tamanho das páginas deste site, a gente viu que uma landing page estática tinha 149 KB de HTML, muito mais do que o texto dela. Quase tudo vinha do cabeçalho.

No App Router do Next.js, um componente com `"use client"` é hidratado no navegador, e para isso as props que ele recebe vão serializadas dentro do HTML. O nosso cabeçalho é um componente cliente, porque acompanha a rolagem e abre o menu no celular. Ele fica no layout e recebia o dicionário de traduções inteiro:

```tsx
<Frame dict={dict} lang={lang} />
```

Usava cinco campos, mas levava junto o portfólio, as galerias de cada projeto e os textos das calculadoras, em todas as páginas.

## Recortes do dicionário

A saída foi passar para cada componente cliente só o que ele usa, com um tipo para cada recorte:

```ts
export type FrameCopy = {
  nav: Dictionary["nav"];
  site: Pick<Dictionary["site"], "name">;
  tools: Pick<Dictionary["tools"], "backLabel">;
  ui: {
    header: Dictionary["ui"]["header"];
    footer: Pick<Dictionary["ui"]["footer"], "ariaLabel">;
  };
};

export function frameCopy(dict: Dictionary): FrameCopy {
  return {
    nav: dict.nav,
    site: { name: dict.site.name },
    tools: { backLabel: dict.tools.backLabel },
    ui: {
      header: dict.ui.header,
      footer: { ariaLabel: dict.ui.footer.ariaLabel },
    },
  };
}
```

```tsx
<Frame dict={frameCopy(dict)} lang={lang} />
```

Se o cabeçalho começar a usar outro texto, o TypeScript reclama até o campo entrar no recorte. Fizemos o mesmo com o formulário de contato e com o carrossel do portfólio, e a landing page caiu para 124 KB.

## O sprite de ícones

Na home tinha outro caso. Os ícones de tecnologia do portfólio vinham de um sprite SVG de 42 KB desenhado dentro da página. Como quem desenhava era o React, ele ia duas vezes, uma no HTML e outra nos dados de hidratação.

Tiramos o sprite da página e passamos a servir como arquivo, com cache:

```ts
export const dynamic = "force-static";

export function GET() {
  const symbols = Object.entries(techIcons)
    .map(
      ([slug, icon]) =>
        `<symbol id="tech-${slug}" viewBox="${icon.viewBox}">${icon.paths
          .map((d) => `<path d="${d}"/>`)
          .join("")}</symbol>`,
    )
    .join("");

  return new Response(`<svg xmlns="http://www.w3.org/2000/svg">${symbols}</svg>`, {
    headers: {
      "Content-Type": "image/svg+xml",
      "Cache-Control": "public, max-age=604800, stale-while-revalidate=86400",
    },
  });
}
```

Os ícones agora apontam para esse arquivo:

```tsx
<use href={`/tech.svg#tech-${tech.slug}`} />
```

O HTML da home caiu de 268 KB para 181 KB. Comprimido, de 78 KB para 39 KB.

Para achar isso em outro projeto, abra o código-fonte de uma página em produção e procure por `self.__next_f.push`. Se ali tiver texto que a página não mostra, tem componente cliente recebendo mais do que usa.
