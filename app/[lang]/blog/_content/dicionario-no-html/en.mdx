Measuring page sizes on this site, we noticed a static landing page had 149 KB of HTML, way more than its text. Almost all of it came from the header.

In the Next.js App Router, a component with `"use client"` gets hydrated in the browser, and for that the props it receives are serialized into the HTML. Our header is a client component, because it follows the scroll and opens the menu on mobile. It sits in the layout and was getting the whole translation dictionary:

```tsx
<Frame dict={dict} lang={lang} />
```

It used five fields, but carried the portfolio, every project's gallery and the calculator copy along with it, on every page.

## Slices of the dictionary

The way out was to give each client component only what it uses, with a type for each slice:

```ts
export type FrameCopy = {
  nav: Dictionary["nav"];
  site: Pick<Dictionary["site"], "name">;
  tools: Pick<Dictionary["tools"], "backLabel">;
  ui: {
    header: Dictionary["ui"]["header"];
    footer: Pick<Dictionary["ui"]["footer"], "ariaLabel">;
  };
};

export function frameCopy(dict: Dictionary): FrameCopy {
  return {
    nav: dict.nav,
    site: { name: dict.site.name },
    tools: { backLabel: dict.tools.backLabel },
    ui: {
      header: dict.ui.header,
      footer: { ariaLabel: dict.ui.footer.ariaLabel },
    },
  };
}
```

```tsx
<Frame dict={frameCopy(dict)} lang={lang} />
```

If the header starts using another string, TypeScript complains until the field makes it into the slice. We did the same for the contact form and the portfolio carousel, and the landing page went down to 124 KB.

## The icon sprite

The home page had another case. The tech icons in the portfolio came from a 42 KB SVG sprite drawn inside the page. Since React was the one drawing it, it shipped twice, once in the HTML and again in the hydration data.

We took the sprite out of the page and started serving it as a file, with caching:

```ts
export const dynamic = "force-static";

export function GET() {
  const symbols = Object.entries(techIcons)
    .map(
      ([slug, icon]) =>
        `<symbol id="tech-${slug}" viewBox="${icon.viewBox}">${icon.paths
          .map((d) => `<path d="${d}"/>`)
          .join("")}</symbol>`,
    )
    .join("");

  return new Response(`<svg xmlns="http://www.w3.org/2000/svg">${symbols}</svg>`, {
    headers: {
      "Content-Type": "image/svg+xml",
      "Cache-Control": "public, max-age=604800, stale-while-revalidate=86400",
    },
  });
}
```

The icons now point at that file:

```tsx
<use href={`/tech.svg#tech-${tech.slug}`} />
```

The home page HTML dropped from 268 KB to 181 KB. Compressed, from 78 KB to 39 KB.

To spot this in another project, open the source of a page in production and search for `self.__next_f.push`. If you see text there that the page doesn't show, some client component is getting more than it uses.
